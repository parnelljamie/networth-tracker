# 05 · UI

A calm, fast personal-finance app that reads like a well-kept statement. Numbers are the hero;
chrome stays quiet. Desktop first (≥ 1280 px), usable down to 1024 px, and a first-class phone
layout for the Android app.

## Design system: "Ledger"

Warm paper, ink rules and serif figures: sections are separated by rules rather than boxed in
cards, big numbers are set in a serif, navy is kept for actions and a brass diamond is the mark.

**Theme**: light and dark, following the OS by default, toggle in the masthead
(`data-theme` on `<html>`). Map shadcn CSS variables to these tokens in `styles/globals.css`:

| Token | Light | Dark | Use |
|---|---|---|---|
| `--page` (shadcn `--background`) | `#f5f2ea` | `#15130f` | app background (paper) |
| `--surface` (shadcn `--card`) | `#fffdf7` | `#1d1a15` | boxed cards, inputs, popovers |
| `--surface-2` (shadcn `--muted`) | `#efeadf` | `#24211b` | hover wash, sunk panels |
| `--ink` (shadcn `--foreground`) | `#1a1e28` | `#ede7da` | primary text, total lines, section rules |
| `--ink-2` | `#484d59` | `#c2baaa` | secondary text |
| `--ink-muted` | `#6a665c` | `#9c9486` | axis labels, captions |
| `--grid` / `--rule-soft` | `#ece6d8` | `#2b271f` | gridlines, rules between rows |
| `--axis` / `--border` | `#ddd6c6` | `#3a342b` | baselines, hairlines |
| `--accent` (shadcn `--primary`) | `#1e3a5f` | `#a9c3e6` | buttons, focus rings, links, the fan chart |
| `--brass` | `#8a6a1f` | `#d1ae62` | the logo mark, milestone dates, wrapper badges |
| `--gain` | `#1f6b2e` | `#5cc46c` | positive change text (with ▲) |
| `--loss` | `#b42f2f` | `#f07a7a` | negative change text (with ▼) |
| `--warn` | `#8f5e00` | `#fab219` | stale data (always with icon + words) |

**Visual reference**: `docs/mockup-ledger/` holds a static mockup of every screen in this design,
light and dark, desktop and phone (open `index.html` through any static server, e.g.
`python -m http.server` in that folder). The figures in it are made up. Match its look; where it
and this document disagree on behaviour, this document wins. `docs/mockup/` is the previous
design, kept for its page-by-page behaviour notes.

**Type**: Newsreader (serif) for page titles, section titles and every standalone figure — the
hero, stat tiles, subtotals (`<Money display />`, or `<Money>` inside a `font-heading` wrapper:
`<Money>` and `<Pct>` inherit their parent's face unless `display` is set). Public Sans for all UI
text and table figures. IBM Plex Mono only for tickers, ledger dates and keyboard hints. Self-host
with `@fontsource-variable/newsreader`, `@fontsource-variable/public-sans` and
`@fontsource/ibm-plex-mono`, falling back to Georgia / `system-ui, "Segoe UI", sans-serif`. Hero
figure 104 px (64 px on phones), weight 500, proportional digits. Stat values 28–32 px. Tables and
axis ticks use `font-variant-numeric: tabular-nums`; big standalone numbers do not. A page opens
with a small uppercase kicker (`.eyebrow`) above its title (`<PageHeader>`).

**Ages** on chart axes read as whole years (`42`) over ranges of four years or more, and as years
and months (`42y 7m`) below that, where whole years would repeat across every tick. Never decimal
years.

**Shape and spacing**: a section (`<Card>`) is a 2 px `--ink` rule with a serif title and no box;
`<Card variant="boxed">` is a paper card (radius 12 px, one hairline) for tiles in a grid —
account cards, goals, other assets. Rows inside a section are separated by `--rule-soft`
hairlines; table headers sit on an `--ink` rule. Inputs and buttons radius 8 px; choice groups are
joined pills (`<Segmented>`), ranges are pills with the active one filled `--ink`. Page gutter
64 px at 1440, 40 px on tablets, 16 px on phones; 40–48 px between sections; content max width
1440 px; no shadows except popovers and sheets.

**Money**: `formatGBP(v)` → `£48,210.55`; compact in axes and tiles `£48.2k`, `£1.23m`; negatives
use a true minus `−£1,234.00`. **Overview rounds balances and totals to whole pounds**
(`<Money whole />` → `£587,841`) — the hero, People, Allocation, Liquidity & debt, ISA meters,
Coming up and the Accounts table. Pence stay everywhere they carry meaning: account detail,
transactions, holdings, and *every* change figure (`DeltaChip`, day changes, movers), which are
small enough that rounding would swallow them. The masthead figure follows the hero. Changes: `▲ £212.40 (0.44%)` in `--gain`, `▼ …` in `--loss`, zero in
`--ink-muted`. Percent inputs show `4.50 %` and send `0.045`.

**Privacy mode** (eye icon in the masthead, shortcut `Shift+P`): every `<Money>` renders `£•••••` with
the same width; charts keep shape but axes and tooltips hide values. Persisted in localStorage.

**Motion**: 150 ms ease-out for hovers/dialogs; no count-up animations; on refetch keep the previous
render at 60% opacity instead of flashing skeletons (skeletons only on first load).

## Chart rules (non-negotiable)

Categorical colours are assigned **by entity, in this fixed order, never by rank**:

| Slot | Entity (category charts) | Light | Dark |
|---|---|---|---|
| 1 | Investments | `#2a78d6` | `#3987e5` |
| 2 | Pensions | `#eb6834` | `#d95926` |
| 3 | Cash | `#1baf7a` | `#199e70` |
| 4 | Property | `#eda100` | `#c98500` |
| 5 | Debts (mortgage, loans, cards) | `#e87ba4` | `#d55181` |
| 6 | Other assets | `#008300` | `#008300` |
| 7 | (spare) | `#4a3aa7` | `#9085e9` |
| 8 | (spare) | `#e34948` | `#e66767` |

Charts that split **by person** or **by scenario** use slots 1..N in sort order and are never shown
in the same view as a category-coloured chart (use a Category | Person toggle). Person avatar
colours are badges only, always next to the name.

- Lines 2 px, round caps. Area fills are the series hue at ~10% opacity. Bars ≤ 24 px thick with a
  4 px rounded data end, square at the baseline, 2 px surface-colour gap between touching bars and
  stacked segments. Markers ≥ 8 px with a 2 px surface ring.
- Gridlines and axes: 1 px solid hairlines (`--grid`, `--axis`). **Dashed strokes mean projection
  only.**
- One y-axis per chart, always. Different units → separate charts.
- ≥ 2 series → a legend is always shown; label only the endpoint or the one series that matters.
  Text uses ink tokens, never the series colour; a swatch next to the text carries identity.
- Every line/area chart has a crosshair + tooltip (date, each series, total); bars have per-bar
  tooltips; hit targets ≥ 24 px. Keyboard focus shows the same tooltip.
- Every chart has a "Table" toggle rendering the same data as a table.
- Donuts only for part-to-whole with ≤ 6 segments; beyond that fold the tail into "Other".
- Status colours (`--gain`, `--loss`, `--warn`) never colour a series.
- Size chart containers to include axis labels; never clip or nest scrollbars.

## App shell

```
┌──────────────────────────────────────────────────────────────────────────────────┐
│ ▲ Waymark  │ Household £512,346     [Search… Ctrl K] ● Live 2m  🔔 👁 ◐ [+ Add] [Quick update] │
│ Overview  People ▾  Property  Pensions  Investments  Other  Projections  Goals   Import  Settings │
├──────────────────────────────────────────────────────────────────────────────────┤
│                                                                                  │
│   KICKER                                                                         │
│   Page title                                              actions / figure      │
│                                                                                  │
│   page content, ruled sections                                                   │
└──────────────────────────────────────────────────────────────────────────────────┘
```
- Masthead (`components/layout/Masthead.tsx`), two rows sharing the page's content column.
  Top row: the wordmark (brass waymarker stone with an upward chevron + serif "Waymark"), the household total (lg+), search
  (`Ctrl K`), the price status pill that also refreshes prices (`● Live · 2m ago`,
  `▲ Prices 3 days old` with icon), the pending-confirmations bell, privacy and theme toggles,
  `+ Add` (account) and **Quick update**. Second row: section tabs underlined in `--ink` when
  active, with People as a menu of each person; Import and Settings sit at the right in muted text.
- Phones (below `md`): a sticky bar — menu, wordmark, refresh, Quick update, bell — and the same
  navigation in a left drawer (`NavDrawer.tsx`) headed by the household total, with People,
  Settings, the sync status (phone role) and the privacy and theme toggles at the foot.
- `Ctrl+K` command palette: jump to any page/account/instrument, run "Refresh prices", "Quick update",
  "Add account", toggle privacy.
- Pending recurring purchases show a badge on a bell icon → popover with a Confirm list.

## Pages

### Overview `/`
Top to bottom, full width, like the front page of a statement:

1. **Hero**: kicker with today's date and the scope; "Together you're worth" (or "Sam is worth")
   beside a `Total | Liquid` toggle; the hero figure; `▲ £… today` and `▲ £… over the year`
   (wording follows the range). Right: scope `Household | person…` and range pills
   `1W 1M 3M 6M YTD 1Y 5Y All`; both apply to everything below.
2. **Chart**: each category over the range (property shown as equity, mortgage folded in) with
   the total as a 2 px `--ink` line; `Categories | Total`; "Show projection" extends the total as
   a dashed line for N years (base scenario). Legend and "View as table" sit under the chart.
3. **Balance sheet**: two bars on one scale — *Own*, split by category, over *Owe* — so the gap
   is the net worth; legend rows `swatch · name · £ · %`.
4. **Liquidity & debt**: four figure columns: Accessible now (liquid), Locked (pensions, property
   equity, LISA), Total debt, Mortgage LTV.
5. **Three columns** (two on tablets, one on phones):
   - **Accounts**: grouped by category (italic serif group name, swatch and subtotal), rows with
     name, provider, staleness when not fresh, owner avatars and value. Row click → account page.
   - **People**: avatar, name, one-month change, scoped net worth and % of household, with a
     neutral `--ink-muted` proportion bar (the avatar carries the person colour); the one-month
     change comes from `/api/networth/history?group_by=person`. Joint ownership footnote. Then
     **Allowances** — one ISA meter per person `£12,000 of £20,000 · 2026/27 · 202 days left`
     (slot-1 blue `#2a78d6` on `#cde2fb`; dark `#3987e5` on `#184f95`) with the pension annual
     allowance as a secondary line — and **This month** (what moved the figure).
   - **Coming up** (next 60 days, stale balances first as "Due"), **Milestones** (next three,
     dates in brass italic), **Today's movers** (top holdings by absolute day change) and
     **Deposit protection**.

Empty state (no accounts): welcome card with three actions: Add people, Add your ISA, Add your mortgage.

### Person `/people/:id`
Header: avatar, name, age (if DOB), scoped net worth, change chips, 1Y sparkline.
No tabs: the page is category stat tiles (value, share) for this person plus an **All accounts**
list grouped by category (same order/labels as Overview's Accounts card) with Edit and Delete
reachable in one click. The per-category detail that used to live in tabs here now lives on the
household pages — Pensions `/pensions`, Investments `/investments`, Property `/property`,
Other `/other` — each of which groups by person rather than being scoped to one.

### Account `/accounts/:id`
Header: name, wrapper badge, provider, owners, value, gain, day change, actions (Edit, Archive).
Tabs depend on valuation method:
- **Holdings** (holdings): TanStack table: Instrument (name, symbol, asset-class chip, `manual`
  badge), Units ✎, Avg cost ✎, Price (native in tooltip, e.g. `9,731p`), Value, Gain £, Gain %,
  Today, Weight; sticky footer with totals and an editable **Cash** row. Inline edit: click cell →
  input → Enter saves via `PUT /holdings/{instrument_id}` with a toast "Recorded as adjustment".
  "Add holding" opens the instrument search combobox (debounced 300 ms; results show symbol, name,
  exchange, currency; last option "Add manual instrument"). Beside the table: weights bar chart.
- **Transactions** (holdings): filterable table; add/edit dialog whose fields change with type
  (BUY/SELL compute amount from units × price + fees, showing the sign); pending rows highlighted
  with Confirm buttons.
- **Balances** (balance/model/amortising): dated entries table (inline add row at top) + line chart.
  Model accounts show the modelled line forward from the latest entry as a dashed segment.
- **History**: value line vs net contributions line (holdings) or value only; range filter row.
- **Plans**: plans targeting this account.
- **Settings**: form for account fields, owners editor (people + share sliders that must total
  100%, "Joint 50/50" preset), expected return, fees, include in net worth, liquidity.

### Property & Mortgage `/property` (tabs per property if more than one)
- KPI row: Property value (est.), Mortgage owed (est.), Equity (with per-person split), LTV,
  Current rate + "Fix ends in 2 y 8 m (31 May 2029)", Monthly payment, Mortgage-free date.
- Chart: property value (slot 4) and mortgage balance (slot 5) from purchase to maturity; history
  solid, future dashed; tooltip shows equity.
- **Overpayment simulator** card: `Extra per month £[ ]`, lump sums list, effect toggle
  (reduce term / reduce payment) → live results via `POST /schedule/simulate` (debounced):
  new mortgage-free date, months saved, interest saved, allowance warnings (warn icon + text).
  "Save as plan" creates an overpayment plan.
- **Rate periods**: horizontal timeline strip (fixed periods as segments, fallback rate after) +
  editable table (start, end, rate %, type, label, payment override).
- **Schedule**: virtualised table grouped by year (collapsible year rows with totals), rate-change
  rows marked, planned overpayments shown; "Export CSV".
- **Valuations & statements**: two small tables (property valuations; mortgage statement balances)
  with "Add" rows, growth-rate setting with a note "applied from the latest valuation".

### Pensions `/pensions`
Household view of every `pension` account — the forward-looking numbers live beside the thing
being projected, as on Property.
- KPI row: Household pensions, Projected at retirement (each person run to *their own* retirement
  age, then summed), account count.
- Chart: pension value, history solid / future dashed, with a 5y/10y/20y/30y horizon toggle.
- One card per person: pension access date (DOB + `pension_access_age`, default 57), retirement
  date, and the pension annual allowance meter (used / remaining / days left).
- Account cards within each person: value, projected value at retirement, monthly contribution
  split (personal / employer / tax relief, derived from that account's recurring plans),
  staleness badge, link to the account page.

Empty state (no pensions): "No pensions yet" with an **Add pension** action.

### Investments `/investments`
Household view of every `investment` account. ISA is a wrapper, not a category, so the "ISA view"
lives here rather than as its own section.
- KPI row: Household investments, Gain (£ and % of cost), Day change, Projected at the horizon.
- Chart: investment value, history solid / future dashed, same horizon toggle.
- **ISA allowance**: one meter per person (used / of limit / remaining / days left) — the same
  `AllowanceMeters` component as Overview's ISA card.
- Accounts grouped by wrapper (ISA, LISA, JISA, GIA) with a per-wrapper subtotal; each card shows
  current value, projected value at the horizon, gain chip and staleness.
- **Combined holdings**: one row per instrument, units and value aggregated across every
  investment account, sorted by value.

Empty state (no investments): "No investments yet" with an **Add investment account** action.

### Other assets `/other`
Card grid; each card: icon by type (car, watch, jewellery, art, collectibles, business, money owed
to me, other), name, owners, modelled value today, rate chip `▲ 3.0 %/yr` or `▼ 15.0 %/yr` (ink
text with icon, not series colour), method, "Last valued £18,000 on 3 Feb 2026", sparkline from
last valuation to +5 years (dashed after today). Debts section below (loans, cards, other
liabilities) with owed amount, rate and payoff date where amortising. Add/edit dialog: name, type,
owners, value + date, annual rate %, method, floor/cap, include in net worth.

### Projections `/projections`
Filter row: scope, horizon slider (1–50 years), scenario select, `Nominal | Today's money`,
`Category | Person` toggle, include property toggle.
- Main chart: stacked area by category (or by person) from today, with vertical hairline milestone
  markers labelled at the top (mortgage-free, pension access, £1m), and a "today" marker.
- Table: values at 1, 5, 10, 20, 30 years and at each person's retirement age.
- Contributions vs growth: stacked area of cumulative contributions (slot 1) and growth (slot 2).
- Range of outcomes: Monte Carlo fan (`03` §10) — p10–p90 and p25–p75 bands in `--accent`, the
  median as a solid `--accent` line, the deterministic projection dashed `--ink`; a sentence gives
  the 80% range and median at the horizon. Honours scope, scenario, horizon, real terms and the
  include-property toggle. Volatility per asset class is editable in the assumptions drawer.
- Scenario comparison: lines for up to 3 selected scenarios (slots 1–3).
- Assumptions drawer: inflation, default returns per asset class (property here is the fallback house growth rate), hover help on each rate, per-account
  return overrides; scenario editor with events list (date, kind, account/plan, amount, label).
- Footnote: "Projections are illustrations based on your assumptions, not predictions or advice."

### Import `/import` (Phase 8)
Wizard: Upload → Profile & column mapping → Instrument matching → Preview & reconciliation →
Commit → Rebuild progress. Import history list with Undo.

### Settings `/settings`
Sections: People (add, edit, colour, DOB, retirement age, include in household, archive) ·
Assumptions · Tax-year rules · Prices (refresh interval, status, test a symbol) · Data (backup now,
backups list, export JSON, data folder path) · Appearance (theme, privacy default, compact tables).

## Quick update dialog (the monthly ritual)
Full-height sheet listing, grouped by person then category, every `balance`, `model` and
`amortising` account: name, last value + date (staleness icon), modelled/expected value in muted
text as a hint, **new value input** (empty by default), date (defaults today). Tab moves down the
list. Footer: "Save 7 updates" → `POST /balances/bulk`, toast, invalidate net worth queries.
Opening it also triggers a non-forced price refresh.

## Frontend architecture

- `src/api/client.ts`: `createClient<paths>({ baseUrl: "/api" })` from openapi-fetch.
- `src/api/hooks/`: one file per area. Query keys: `["networth","current",personId]`,
  `["networth","history",personId,range,groupBy]`, `["accounts",filters]`, `["account",id]`,
  `["holdings",accountId]`, `["transactions",accountId,filters]`, `["schedule",accountId]`,
  `["projection",params]`, `["settings"]`. Mutations invalidate `["networth"]` plus their own keys.
- Price status polls `/prices/status` every 60 s; `networth/current` refetches every 5 min while
  the window is visible.
- Components to build once and reuse: `Money`, `Pct`, `DeltaChip`, `StatTile`, `PersonAvatar`,
  `OwnersEditor`, `PercentInput`, `MoneyInput`, `DateInput`, `StalenessBadge`, `CategoryIcon`,
  `RangeFilter`, `ChartCard` (title, legend, table toggle, container), `AreaStackChart`,
  `LineChart`, `DonutChart`, `BarList`, `Sparkline`, `Meter`, `EditableCell`, `DataTable`,
  `InstrumentSearch`, `AccountFormDialog`, `TransactionDialog`, `PlanDialog`, `QuickUpdateSheet`,
  `CommandPalette`, `EmptyState`.
- Forms: zod schemas mirror API constraints (shares sum to 1, rates between −1 and 1, dates valid).
